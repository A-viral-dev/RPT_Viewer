## Project Purpose

Finacle generates `.RPT` files that are plain-text, fixed-width documents. These are not machine-readable without specialized parsing. This tool provides:

- A drag-and-drop upload UI (runs on localhost via NiceGUI)
- Intelligent, preset-driven parsers for different Finacle report types
- Automatic metadata extraction (Account Name, SOL ID, Statement Period, etc.)
- Indian currency formatting (lakhs/crores grouping: `1,00,00,00,000.00`)
- Export to **CSV**, **Excel**, **JSON**, and **PDF**
- Session memory — reloads your last file automatically on restart

## Architecture Overview

```
main.py (UI Layer — NiceGUI)
   │
   ├── Handles file upload, preset selection, data grid, metadata cards
   ├── Manages session state (in-memory dict: state['df'], state['metadata'])
   ├── Auto-restores last file on startup via saved app_settings.json
   │
   └── calls: parse_file() ── parser.py (Parsing Engine)
                  │
                  ├── Routing Table:
                  │     CC001 → logic_cc_general_cc001() ─┐
                  │     Term Loan / Escrow → logic_term_loan() ─┤ both call
                  │                                              parse_statement()
                  │     Depreciation → logic_depreciation()
                  │     Interest Reports → logic_interest_report()
                  │     Fallback → parse_fixed_width_generic() or parse_delimited_generic()
                  │
                  └── Regex-first statement primitives:
                        classify_line() / extract_amounts()
                        signed_balance() / choose_movement() / split_cheque()
                        apply_base_cleanup() / apply_narration_merger()

config.py (Preset Registry)
   │
   ├── FINACLE_CLEANUP — shared noise filtering rules (ignore_prefixes, stop_markers)
   ├── TERM_LOAN_CONFIG — Term Loan & Escrow shared configuration (single source of truth)
   └── PRESETS dict — all named presets with their per-preset settings

export.py (Export Engine)
   ├── export_to_csv()
   ├── export_to_excel()
   ├── export_to_json()
   └── export_to_pdf()  ← Uses fpdf2, generates landscape A4 with metadata + full table
```

## Parsing System Deep Dive

### Key Design Principle: Regex-First, Accounting-Safe

Statement parsing never slices by character offset. Each statement line is
classified by shape, currency tokens are extracted by regex, and the
debit/credit side is proven from the running balance — not from a column width.
Report-specific behaviour is preserved through a small set of options on one
shared engine, so a fix in one report type cannot silently corrupt another.

**Line classification** (`classify_line`) returns one of `transaction`,
`narration`, `rule`, `page_total`, `blank`, or `other`:

| Pattern | Meaning |
|---|---|
| `^(\d{2}-\d{2}-\d{2})(?:\s\|$)` | dated transaction row (also excludes `As On …` headers) |
| `^\s{2,}\S` | indented narration continuation |
| `-{3,}` | horizontal rule |
| `page\s+total` | page subtotal |

**Currency extraction** (`extract_amounts`) uses
`\d+(?:,\d{2,3})*\.\d{2}(?:Cr|Dr)?`. Because there is no lookbehind, two tokens
printed without a gap (e.g. `93,50,96,546.14102,67,68,817.57Cr`) still split
correctly. Opening-balance rows that print a bare integer (`0`) fall back to
`(?<=\s)\d+(?:Cr|Dr)?\s*$`.

**Balance-delta classification** (`choose_movement`, `signed_balance`):

1. Read the signed balance: `Cr` is positive, `Dr` is negative, an unsuffixed
   balance on a CC/OD statement is negative (debit).
2. Compute `delta = balance_current - balance_previous`.
3. Pick the candidate token whose value equals `|delta|`; `delta > 0` is a
   **DEPOSIT**, `delta < 0` is a **WITHDRAWAL**.
4. Column position (taken from the live `WITHDRAWALS`/`DEPOSITS` header line)
   is used **only** when no previous balance exists, e.g. the first row.

**Cheque isolation** (`split_cheque`) requires at least two spaces plus a
trailing 3–7 digit reference: `\s{2,}(\d{3,7})$`. This separates a genuine
cheque column (`:Normal             661`) from a reference embedded in
particulars (`DEAL ID 7149160`, `RTGS-HDFCR64465004822975445-SAMP`).

**Text cleaning** (`clean_text`) collapses fixed-width padding with
`re.sub(r'\s+', ' ', value).strip()`, so `PARTICULARS` and `Narration` never
retain double spaces.

---

### `parse_statement` — shared engine

Both statement families call `parse_statement()` and differ only by options:

| Option | CC001 | Term Loan / Escrow |
|---|---|---|
| `require_narration_indent` | `False` (CC footers can be unindented) | `True` (ignore unindented report headers) |
| `stop_at_footer` | `True` | `False` |
| `default_skip_rows` | `22` | `24` |

**Output columns** (both): `DATE, PARTICULARS, CHQ.NO., WITHDRAWALS, DEPOSITS, BALANCE, Narration`

**Noise handling**: `ignore_prefixes` and `stop_markers` still come from
`FINACLE_CLEANUP`; branch headers are matched generically with
`^[A-Z]{3,6}\s+BRANCH,` rather than a hardcoded branch name.

**Narration**: Indented lines without a date are stored as blank-date rows.
`apply_narration_merger()` then appends their text to the preceding
transaction's `Narration` column.

**Shared Configuration**: `TERM_LOAN_CONFIG` in `config.py` is a single Python
dict that both `Finacle - Term Loan (.RPT)` and ` Escrow Account` presets point
to. Any change to this dict automatically affects both presets.

---

### `logic_depreciation` — Fixed Asset Depreciation

**Input**: Pipe-delimited (`|`), `skip_rows = 13`
**Output columns**: `SNO, ASSET_NO, ITEM NAME, PURCH DATE, BLOCK_AMT, D_RATE, ACTUAL_DEP, QTR_DEP, MAJOR_CATEGORY, CATEGORY, METHOD`

**Special**: Uses a **stateful parser** that tracks hierarchical context. Line
detection is regex-based; `|` remains the field delimiter:
- `MAJOR\s+CATEGORY\s+(.+)` → updates `current_major`
- `CATEGORY:\s*(.*?)(?:\s+DEPRECIATION\s+METHOD:\s*(.+))?$` → updates `current_cat` / `current_method`
- `^\s*\d+\s*\|` → data row; the row inherits the current context and has
  `MAJOR_CATEGORY`, `CATEGORY`, and `METHOD` appended automatically.

---

### `logic_interest_report` — Interest Reports (LA001, LA030, OD028, CC001 & CC002)

**Input**: Pipe-delimited (`|`), `skip_rows = 12`
**Output columns**: 19 fixed financial columns (see `parser.py`)

Row/caption detection is regex-based (`^\|.*\|$`, `^(?:SCHM|CODE)$`) while `|`
remains the field delimiter. Header fragments and caption lines are filtered
out; rows must carry at least one of scheme code/description/account/name.
Numeric columns like `EFFECTIVE ROI`, `SANCTIONED LIMIT`, `BALANCE OUTSTANDING`
are auto-converted to float.

### Shared Utilities

**`apply_base_cleanup(df, ignore_prefixes, stop_markers)`**
- Row-by-row filter on the first column value.
- Drops rows whose text starts with any `ignore_prefix`.
- Stops processing entirely when a `stop_marker` is found (useful for summary footers).

**`apply_narration_merger(df, ignore_prefixes, stop_markers)`**
- First calls `apply_base_cleanup`.
- Scans sequential rows. When a row has an empty date field, it appends all non-empty cell text to the preceding row's **`Narration`** column (never PARTICULARS — these are kept clean).

## Configuration System

All configuration lives in **`config.py`**.

### `FINACLE_CLEANUP`
A shared dict of noise patterns used by most presets:
```python
FINACLE_CLEANUP = {
    "ignore_prefixes": ['page tota', 'grand tot', 'as on', 'sample bank', '---', ...],
    "stop_markers": ['as on ', 'clrbal:', 'we are', ...]
}
```

### `TERM_LOAN_CONFIG`
Extracted as a standalone constant so both Term Loan and Escrow Account presets point to it:
```python
TERM_LOAN_CONFIG = { "skip_rows": 24, ..., **FINACLE_CLEANUP }
PRESETS["Finacle - Term Loan (.RPT)"] = TERM_LOAN_CONFIG
PRESETS[" Escrow Account"] = TERM_LOAN_CONFIG  # Same object, not a copy
```
**⚠️ AI Agent Note**: To change Term Loan or Escrow behavior, only edit `TERM_LOAN_CONFIG`. Do NOT duplicate values into both presets.

### `get_saved_settings()` / `save_settings()`
Manages `app_settings.json` which stores:
- `preset`: last selected preset name
- `last_file`: absolute path to last loaded file copy (`last_session.rpt`)
- `original_filename`: original filename for display in the header badge

## UI Features

Built with **NiceGUI** running on `http://127.0.0.1:8080`.

| Feature | Description |
|---|---|
| **Preset Selector** | Dropdown in header; changing it immediately re-parses the current file |

## Session Persistence

On every file upload:
1. The uploaded file is saved as `last_session.rpt` in the project directory.
2. `app_settings.json` is updated with its path and original filename.

On app startup:
1. `app_settings.json` is read.
2. If `last_file` exists on disk, the app auto-parses it using the saved preset.
3. The data grid and metadata cards are populated before the user interacts.

**Reset** clears `last_file` from `app_settings.json`, breaking the auto-load cycle.

## Adding a New Preset (for AI Agents)

To add a completely new report type, follow these steps:

### Step 1 — Add configuration to `config.py`
```python
PRESETS["My New Report"] = {
    "skip_rows": 18,
    "separator": "",
    "fixed_widths": "",
    "merge_narration": True,
    "metadata_mappings": { "Account": "A/C Name" },
    **FINACLE_CLEANUP  # include noise filters unless this report is very different
}
```

### Step 2 — Add logic to `parser.py`
```python
def logic_my_new_report(filepath, options):
    skip_rows = options.get('skip_rows', 18)
    data = []
    cols = ["DATE", "COL_A", "COL_B", "BALANCE", "Narration"]
    amt_pattern = re.compile(r'(\d+[\d,]*\.\d{2}(?:Cr|Dr)?)')
    
    try:
        with open(filepath, 'r', encoding='utf-8', errors='replace') as f:
            for line in f.readlines()[skip_rows:]:
                # ... your parsing logic ...
                pass
        df = pd.DataFrame(data, columns=cols)
        if options.get('merge_narration'):
            df = apply_narration_merger(df, options.get('ignore_prefixes'), options.get('stop_markers'))
        return df
    except Exception as e:
        logging.error(f"My New Report Logic Error: {e}")
        return None
```

### Step 3 — Register in the dispatcher (`parser.py`)
```python
# Inside parse_file(), add to the routing table:
if preset == "My New Report":
    return logic_my_new_report(filepath, custom_options)
```

**That is all that is needed.** No changes are required to `main.py` or `export.py`. The new preset will automatically appear in the UI dropdown.

## Known Constraints & Edge Cases

| Issue | Current Handling |
|---|---|
| Large amounts (crores) in Term Loan can shift column positions | Solved: debit/credit comes from the signed balance delta, so no column threshold is involved |
| Opening Balance row has `0` with no decimal | Solved: `(?<=\s)\d+(?:Cr|Dr)?\s*$` fallback for bare balances |
| Two amounts printed with no separator | Solved: `\d+(?:,\d{2,3})*\.\d{2}(?:Cr|Dr)?` has no lookbehind, so tokens split at the decimal boundary |
| "As On" header lines contain a valid date pattern | Solved: `^(\d{2}-\d{2}-\d{2})(?:\s\|$)` anchors the date to the start of the line and a separator |
| Cheque numbers leaking into particulars | Solved: only a 2+ space gap followed by 3–7 trailing digits is treated as a cheque |
| Branch header lines leaking into narration | Solved: indentation check plus a generic `^[A-Z]{3,6}\s+BRANCH,` filter |
| `₹` symbol unsupported by PDF Helvetica font | Solved: auto-replaced with `Rs.` during PDF generation |
| Escrow reports differ only in name, not format | Solved: `TERM_LOAN_CONFIG` dict shared by reference — both presets are identical |
